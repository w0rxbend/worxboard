01 · features

What's in it

📐

Exact ErgoDox layout

The switch centres, the column stagger and the 25° thumb cluster come from the original ErgoDox PCB. The thumb keys match it within 0.002 mm, the main keys match the spec table within 0.0001 mm.

📟

A display on each half

A Sharp LS011B7DH03 memory LCD (160 × 68) on a nice!view-class module sits where the inner top key was, behind a raised bezel. Left: the ZMK status screen. Right: a custom lock-indicator screen.

🧠

On-board RP2040

No controller daughterboard. The support circuit is derived from the Corne v4.1: 16 MB QSPI flash, a 12 MHz crystal, an LDO and ESD arrays. JLCPCB or PCBWay fits all 201 parts per half.

🔌

USB-C on both halves

Plug the host into the left half. The right USB-C gives power and UF2 flashing. Schottky diodes let you plug in both at once without back-feeding either host.

🔗

A careful wired split

ZMK's wired split on UART0 at 115 200 baud over a straight TRRS cable. The tip carries only 1 kΩ-limited data, power sits on Ring2 behind a 250 mA polyfuse, and jumper JP1 turns cable power off.

🔥

Hot-swap, no PCB soldering

MX hot-swap sockets on the bottom, 2u plate-mount stabilisers on two thumb keys per half. The fab fits every PCB part, the display socket and the LEDs included; you solder only the displays' header pins.

🌈

Per-key RGB

Rev B puts an SK6812MINI-E under every switch, reverse-mounted in a cutout so it shines up through the switch's south-facing LED window. ZMK runs each half's chain as underglow: whole-board effects, hue and brightness from the layer-1 thumbs, relayed to the right half. No per-key colours; brightness capped at 8 % for one-cable power. Not yet tested on hardware.

🧱

CNC aluminium case

Each half: a 6061-T6 top shell with the 1.5 mm plate milled into it, a 6061-T6 tray and a printed 3 mm spacer. Bead blast plus anodize, a raised bezel over the display.

🦵

Tent legs like the EZ

Three mounts per half at the stock ErgoDox EZ positions. Each takes a custom aluminium leg with a TPU foot cap, clamped by an M3 × 12 collarless thumbscrew and a friction washer.

🤖

Generated, not drawn

Schematic, placement, routing, DRC, fab files, case, physical layout and docs tables are all scripts, run headless in digest-pinned containers with seeded ids, so a rebuild gives byte-identical boards.

⚡ Power path, each half

USB-C VBUS→D1 Schottky→VSYS ≈ 4.6 V→U3 AP2112K→3V3
VSYS→JP1 bridged→F1 PTC 250 mA→VLINK · Ring2
VSYS→U6 SY6280AAC · GP23→VLED · 37 LEDs

One cable is enough: the far half runs from VLINK at about 4.4 V. Each VBUS reaches VSYS only through its own D1, so two hosts never back-feed each other. VLED stays off until the firmware enables it.

03 · layout

Layout and matrix

On each half, the inner top key C6R0 is replaced by a vertical 14 × 36 mm display module. Rev B sets its bottom edge 1.0 mm behind the old cell boundary, 0.4 mm short of the C6R1 key well, so no other key moves. Both PCBs share one matrix netlist; the right half reverses its columns in the device tree.

What changed from an ErgoDox EZ

  • Inner top key replaced by the display, so each half has 37 keys
  • Lighting: an SK6812MINI-E under every switch, run by ZMK as underglow (whole-board effects, not per-key colours)
  • Outline: jack tabs removed, back edge straightened, a TRRS bump on the inner edge
  • Mounting hole #7 moved from under the display to (88.0, 37.135)
  • Connectors: USB-C on both halves at the back edge, TRRS on the inner edge
  • Firmware: ZMK, base layer from QMK ergodox_ez layer 0; LEFT / RGHT move to layer 1
  • Case: CNC 6061-T6, about 1–2 mm smaller than the photo-measured EZ case

🎹 What goes on top

74 MX-compatible plate-mount switches, 3- or 5-pin (Choc and Alps do not fit). For the LEDs, pick switches with an LED window or a clear housing; shine-through keycaps let the light through the legends.

Keycaps: 58 × 1u, 12 × 1.5u (8 horizontal in the outer columns, 4 vertical in the inner columns) and 4 × 2u vertical thumbs. A standard 76-key ErgoDox keycap set covers it, with 2 × 1u spare.

Add 4 Cherry-style clip-in 2u plate-mount stabilisers for a 1.5 mm plate; screw-in PCB-mount stabilisers do not fit.

⚡ Flash it

  1. Download worxboard-firmware from a green firmware run.
  2. Get the RPI-RP2 drive: a blank board shows it by itself; otherwise double-tap RESET, or hold BOOT, tap RESET and release BOOT.
  3. Drag worxboard_left_central.uf2 onto the left half and worxboard_right_peripheral.uf2 onto the right, each through its own USB-C.

Unlock ZMK Studio with &studio_unlock on layer 2 and edit the keymap live in the Studio web app. If both screens read upside down, set CONFIG_WORXBOARD_DISPLAY_ROTATION_270=y.

The LEDs are one ZMK underglow strip per half. They start dim, red and solid; the layer-1 thumbs step the effect (solid, breathe, spectrum, swirl), toggle them and set hue and brightness, and a press on the left also sets the right. Brightness is capped at 8 %; raise it only with both halves on their own USB-C and JP1 cut (firmware.md).

Known open issues

  • Not built yet. The displays, the wired split, the forwarding of the lock indicators, the role-swap firmware and the XOSC start-up with the new crystal are untested on hardware. The case fit (USB-C and TRRS plug seating, the BOOT/RESET pin holes, C6R1 keycap clearance with the display set back) also waits for a real board; check it on a 3D-printed test top.
  • LEDs untested. The chain's timing through the U7 buffer, VLED switching and U6's current limit, the real current at the brightness cap and the RGB commands relayed to the right half have only been checked in the design files and the ZMK source. ZMK drives the chain as underglow: no per-key colours.
  • Brightness cap. 8 % so one cable can feed both halves (the right half's LEDs run through the 250 mA polyfuse). Raise it, to 20 % at most, only in split-power mode with JP1 cut on both halves; that is a local build.
  • Right-half settings writes. The right half now saves its own RGB state; flash writes lock interrupts, and whether that can drop a frame on the split UART is unmeasured.
  • USB-C plug. The cable needs a plug with at least 8 mm of bare metal shell to latch in the case; a common plug stops about 1.2 mm short.
  • Display orientation rests on ZMK's code and the vendor's images, not a datasheet. If the screens read upside down, one Kconfig line flips them.
  • Fab placement. Every JLC CPL placement is proven against JLC's own footprints, but JLC does not document its bottom-side convention: check the sockets, diodes and LEDs in the placement preview. The socket C41430893 is a second-source part with no assembly report yet. At PCBWay, use only its own files, never the JLC CPL.
  • Stock moves daily: re-check it on the day you order. J3 (C27985230) has no drop-in alternate that fits the case.
  • 3D models. KiCad has no model for the USB-C, the TRRS jack or the hot-swap socket, so the board STEP lacks those bodies; the case fit check adds their envelopes.
  • Release packaging. release.yml still packs KiKit's raw fab files, not pcb/production/.
  • Firmware image and heap. The build runs in the floating zmk-build-arm:stable image; LVGL heap use has not been measured on hardware.
  • RP2350A target: settings, the RGB state included, do not persist, because the flash map and NVS are forced off.
  • Licence split (GPL-3.0 code, CERN-OHL-S-2.0 hardware) still needs the maintainer's confirmation.
